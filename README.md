# metka_Bluetooth — дверной замок на ESP32, который открывается при приближении телефона

ESP32 следит по Bluetooth LE за сопряжёнными телефонами. Когда вы подходите к двери с телефоном, замок сам открывается. Чужие устройства игнорируются. Управление (добавление телефонов, калибровка, настройки) идёт с телефона по Bluetooth через страницу в Chrome. Wi-Fi нужен только для обновления прошивки.

Проект сделан для электрозамка, который открывается подачей питания на 2 секунды. Основной сценарий (автооткрытие, страница управления, обновление по Wi-Fi) проверен на реальной плате. Остальное написано по тем же правилам, но на железе может потребовать правок.

## Как это работает

**Определение приближения.** Телефон сопряжён с ESP32 как Bluetooth-клавиатура (HID), поэтому Android подключается к нему сам, без приложения. ESP32 измеряет силу сигнала телефона (RSSI) 10 раз в секунду и берёт медиану за 1 секунду, чтобы одиночные выбросы не влияли.

**Открытие.** Для каждого телефона хранится свой уровень «у двери» (дБм). Дверь открывается, когда сглаженный сигнал **пересёк этот уровень снизу вверх** (вы приблизились) и продержался выше него заданное время (по умолчанию 1 секунда). Реле срабатывает на 2 секунды.

**Повторное открытие.** После открытия телефон считается «у двери»: пока вы стоите рядом или проходите вплотную к замку, дверь повторно не откроется. Состояние «телефон ушёл» наступает, когда сигнал стал слабее уровня на запас (по умолчанию 6 дБм) и продержался там заданное время (по умолчанию 120 секунд). После этого следующее приближение снова откроет дверь.

**Защита после включения.** Первые 60 секунд после подачи питания дверь не открывается, чтобы после отключения света она не открылась от телефонов, которые находятся дома.

**Авторизация.** Новые телефоны принимаются только в окне добавления (90 секунд после короткого нажатия BOOT или команды со страницы). Чужие устройства отключаются. Команды управления принимает только сопряжённый и не заблокированный телефон, и только по зашифрованному соединению.

**Wi-Fi.** При включении питания точка доступа работает 10 секунд как «аварийный вход», потом выключается. Включить её снова можно кнопкой или командой со страницы управления. Пока Wi-Fi включён, автооткрытие приостановлено, потому что радио одно на Wi-Fi и Bluetooth, и замеры сигнала в это время недостоверны.

## Что нужно (компоненты)

| Деталь | Заметки |
|---|---|
| Плата ESP32 (ESP-32D / «ESP32 Dev Module», 4 МБ флеша) | Нужен Bluetooth LE. Платы ESP32-S2 не подойдут, у них нет Bluetooth |
| Понижающий DC-DC преобразователь до 5 В | Питает ESP32 от питания замка (например 12 В). Берите с запасом по току (от 1 А) |
| Реле | См. ниже: тип зависит от питания замка |
| Электрозамок | Открывается подачей питания |
| Кнопка выхода (необязательно) | Нормально разомкнутая, между GPIO27 и GND |
| Провода, клеммы, предохранитель | Предохранитель на питание замка |
| Диод 1N4007 (для замков постоянного тока с катушкой) | Параллельно замку, катодом к плюсу |

**Какое реле брать.** Твердотельное реле **SSR-25DA** коммутирует только **переменный** ток. Если ваш замок питается постоянным током (обычно 12 В), нужно либо механическое реле (например модуль с SRD-05VDC), либо MOSFET-модуль для постоянного тока. Для замка на переменном токе SSR-25DA подходит. Сначала узнайте, на каком токе работает ваш замок.

**Опасное напряжение.** Если замок питается от сети 220 В, работы с этой частью делайте только при отключённом питании и если умеете. Низковольтная часть (ESP32, кнопка) безопасна, силовая нет.

## Схема подключения

```
 Питание замка (например 12 В DC)
   +  ───────┬───────────────────────┐
             │                       │
        [DC-DC → 5 В]           [РЕЛЕ: контакты]──── Электрозамок ──── (−) питания
             │                    (силовая часть)
     5 В ────┴──► ESP32 VIN (5V)
     GND ────────► ESP32 GND ─────────┬───── общий минус (GND)

 ESP32 GPIO26 ────────► IN реле (управляющий вход)
 ESP32 GND    ────────► GND реле
 ESP32 5V/VIN ────────► VCC реле (для модуля с питанием 5 В)

 Кнопка выхода:  GPIO27 ──── кнопка ──── GND   (внутренняя подтяжка включена в коде)
```

| Пин ESP32 | Назначение |
|---|---|
| GPIO26 | Управление реле (по умолчанию срабатывает от HIGH) |
| GPIO27 | Кнопка выхода на GND (необязательно) |
| GPIO2 | Встроенный светодиод |
| GPIO0 | Кнопка BOOT на плате |
| VIN / 5V | Питание 5 В от DC-DC |
| GND | Общий минус |

Если ваш модуль реле срабатывает от LOW, переключите «Реле срабатывает от» на странице управления в разделе «Система».

Для твердотельного реле SSR: плюс управляющего входа подключается к GPIO26, минус к GND, а силовые клеммы реле включаются в разрыв линии питания замка.

## Подготовка Arduino IDE

1. Установите [Arduino IDE](https://www.arduino.cc/en/software).
2. **File → Preferences → Additional boards manager URLs**, добавьте:
   `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
3. **Tools → Board → Boards Manager**, установите «esp32 by Espressif Systems» версии **2.0.x** (проверено на 2.0.17). Версия 3.x не проверялась.
4. **Tools → Manage Libraries**, установите **NimBLE-Arduino** (автор h2zero) версии **1.4.x**. С версией 2.x скетч не соберётся.
5. Настройки в меню Tools:
   - Board: **ESP32 Dev Module**
   - **Partition Scheme: «Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS)»**. Это обязательно: для обновления по Wi-Fi нужны два раздела под программу. Со схемой «Huge APP (No OTA)» обновление по Wi-Fi вызывает аварийную перезагрузку.
   - Остальное можно оставить по умолчанию.

Эти настройки лучше не менять после первой прошивки: при смене схемы разделов по USB обновление по Wi-Fi может перестать работать.

## Первая прошивка по USB

1. Откройте `DoorLock/DoorLock.ino` (папка должна называться `DoorLock`, как и файл).
2. Подключите плату по USB, выберите порт и нажмите **Upload**.
3. Откройте Serial Monitor (115200). При запуске должны появиться строки вида:
   - `Запуск v5.2 (дата время), причина: включение питания`
   - `OTA-разделов: 2 (нужно 2). Раздел: найден`
   Если «OTA-разделов: 1», значит, выбрана неправильная схема разделов, перепрошейте по USB с правильной.
4. После первого запуска **смените PIN и пароли** (см. «Безопасность»).

## Страница управления

Страница `docs/index.html` работает по **Web Bluetooth**: только **Chrome на Android** (и Chrome на компьютере), и только по **HTTPS**. Safari на iPhone Web Bluetooth не поддерживает.

**Вариант 1: GitHub Pages (рекомендуется).**
1. В репозитории: **Settings → Pages**.
2. Source: **Deploy from a branch**, ветка `main`, папка **`/docs`**. Сохраните.
3. Страница будет доступна по адресу `https://velsati86-beep.github.io/metka_Bluetooth/` (через пару минут).
4. Откройте адрес в Chrome на телефоне, меню → «Добавить на главный экран».

**Вариант 2:** положите `docs/index.html` на любой свой HTTPS-хостинг (например Netlify Drop).

Страница ничего не отправляет в интернет: она говорит с замком напрямую по Bluetooth.

## Первое сопряжение и настройка

1. Коротко нажмите кнопку **BOOT** на плате (меньше 2 секунд). Светодиод начнёт мигать, окно добавления открыто 90 секунд.
2. На телефоне: **Настройки → Bluetooth → Добавить устройство → «Door-Lock»**, введите PIN. По умолчанию это `000000`.
3. Откройте страницу управления в Chrome, нажмите **«Подключиться по Bluetooth»** и выберите «Door-Lock». Первые несколько секунд замок проверяет телефон, страница пишет «подождите».
4. Следующие телефоны добавляются кнопкой **«Начать добавление»** на странице или снова кнопкой BOOT.
5. **Запишите уровень «у двери»:** встаньте у двери с телефоном там, где обычно стоите, и нажмите у нужного телефона **«Я у двери — записать»**. Предварительно выключите Wi-Fi (кнопка на странице), иначе замеры недостоверны. Уровень записывается на 3 дБм слабее текущего сигнала.
6. Или задайте уровень вручную кнопкой **«Задать уровень вручную»** (число от −110 до −25 дБм). Чем ближе к нулю, тем ближе нужно подойти.

Подсказка по числам: −50 это почти вплотную, −60 около метра, −70 два–четыре метра. Цифры примерные, многое зависит от телефона и двери (металл сильно глушит).

## Параметры

Все параметры меняются на странице управления.

| Параметр | По умолчанию | Смысл |
|---|---|---|
| Уровень по умолчанию | −65 дБм | Для телефонов, у которых уровень «у двери» не записан |
| «Ушёл», если слабее уровня на | 6 дБм | Запас, после которого засчитывается уход |
| Быть «ушедшим» до повторного открытия | 120 с | Сколько секунд сигнал должен быть слабым |
| Сигнал должен держаться, сек | 1 с | Защита от случайного скачка перед открытием |
| Не открывать после включения | 60 с | Защита после подачи питания |
| Импульс на реле | 2000 мс | Сколько держится реле |
| Мощность Bluetooth | −12 дБм | Чем больше, тем дальше связь и тем больше расход |
| Выключать Wi-Fi через | 60 с | Минимум 30 с, чтобы Wi-Fi не остался включённым навсегда |

Для каждого телефона можно переименовать, заблокировать (на время или бессрочно), разблокировать и удалить. Также на странице есть журнал событий и раздел «Система» (PIN, имя Bluetooth, полярность реле, перезагрузка).

## Кнопки

| Действие | Результат |
|---|---|
| Короткое нажатие BOOT (меньше 2 с) | Окно добавления телефона на 90 секунд |
| Удержание BOOT 2–7 с | Включить Wi-Fi (для обновления прошивки) |
| Удержание BOOT 10 с | Сброс сетевых настроек и паролей (сопряжённые телефоны сохраняются) |
| Кнопка выхода (GPIO27), нажатие | Открыть дверь |
| Кнопка выхода, удержание 5 с | Включить Wi-Fi |

Кнопка выхода позволяет выйти без телефона и служит запасным способом открыть дверь.

## Wi-Fi и обновление прошивки

Обновлять прошивку можно без USB.

1. Включите Wi-Fi: кнопкой «Включить Wi-Fi» на странице управления (раздел «Wi-Fi»), удержанием BOOT 2–7 секунд или удержанием кнопки выхода 5 секунд. Страница покажет имя сети и пароль точки доступа и данные для входа.
2. Подключите телефон или компьютер к сети замка (по умолчанию `DoorLock-ESP32`, пароль `Zamok-7294-Dver`). На телефоне на время обновления лучше выключить мобильный интернет, иначе Android может сбросить сеть без интернета.
3. Откройте `http://192.168.4.1` (логин `admin`, пароль `pass`, если не меняли).
4. В Arduino IDE получите файл: **Sketch → Export Compiled Binary**. Нужен `.bin` **без** слов `bootloader` и `partitions` в названии.
5. Выберите файл, нажмите **«Загрузить .bin»**. Замок остановит Bluetooth, запишет прошивку и перезагрузится сам.
6. Проверьте результат на странице управления в блоке «Система»: время сборки в «Версии прошивки» должно измениться. Там же показано «обновление по Wi-Fi: доступно ✓».

Если на странице написано, что схема разделов не поддерживает обновление, залейте скетч один раз по USB с правильной схемой (Minimal SPIFFS).

## Безопасность

- **Смените значения по умолчанию.** Сразу после первой прошивки поменяйте PIN и имя Bluetooth на странице управления («Система»). Пароли Wi-Fi и сервисной страницы можно сменить командами `set appass`, `set webpass`, `set apssid` (см. [PROTOCOL.md](docs/PROTOCOL.md)).
- **Сопряжение.** Новый телефон можно добавить только в окне, которое открывается физически (кнопка BOOT на плате) или командой от уже сопряжённого телефона.
- **Определение по силе сигнала не идеально.** Сигнал зависит от стен, положения телефона и помех. Это удобство, а не высокая защита. Оставьте запасной способ открыть дверь (механический ключ, кнопка выхода).
- **Wi-Fi выключен** почти всё время, поэтому в обычной работе точки доступа для взлома просто нет.
- Силовая часть (220 В) и работа с замком выполняются на ваш страх и риск.

## Диагностика

| Симптом | Что делать |
|---|---|
| Страница пишет «No Services matching UUID … found» | Телефон помнит старый список служб замка. Удалите «Door-Lock» в настройках Bluetooth, выключите и включите Bluetooth, сопрягите заново (BOOT, PIN) |
| Список устройств при подключении зависает | Страница показывает только устройства с именем «Door…». Если замка нет, нажмите «Показать все устройства». Под кнопкой написано, на каком шаге остановка |
| «Замок проверяет телефон, подождите» | Нормально первые несколько секунд после подключения. Если не проходит, телефон не сопряжён: добавьте его заново |
| Дверь не открывается | В журнале на странице посмотрите: есть ли «подключился», не стоит ли «уже открывал, ждёт ухода», не включён ли Wi-Fi (при нём автооткрытие приостановлено), не прошло ли 60 секунд после включения питания |
| Открывается слишком рано или поздно | Измените уровень «у двери» вручную (шагами по 3–5 дБм) или запишите заново без Wi-Fi |
| Обновление по Wi-Fi: «Ошибка связи», перезагрузка | Проверьте схему разделов (должно быть «OTA-разделов: 2»). Если «1», залейте по USB со схемой Minimal SPIFFS |
| В журнале «ПРОСАДКА ПИТАНИЯ» | Слабый блок питания или DC-DC: возьмите с запасом по току, добавьте конденсатор 470–1000 мкФ на питание платы |
| В Serial Monitor `wifi_netif … failed` при выключении Wi-Fi | Шум библиотеки ESP32 при выключении Wi-Fi, на работу не влияет |

Журнал событий виден на странице управления и в Serial Monitor (115200).
